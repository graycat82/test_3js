# 1단계와 2단계 검증 기록

검증일: 2026-10-18. 범위는 개발·배포 기반과 전체 외형·기본 장면이다.

**실행 환경과 결과**

| 항목 | 결과 |
|---|---|
| 로컬 환경 | Windows, Node 24.18.0, npm 11.16.0 |
| 설치 재현 | Vite 서버 종료 후 `npm ci` 성공, 감사 결과 취약점 0개 |
| 타입 검사 | `npm run typecheck` 통과 |
| 단위 테스트 | `npm test` 3개 통과; 키 배열·주요 부품·유한 좌표·키 겹침과 매몰 검증 |
| 프로덕션 빌드 | `npm run build` 성공 |
| 로컬 제공 경로 | `http://localhost:4173/test_3js/` |
| 데스크톱 화면 | 1280×900에서 초기 시점과 앞·뒤·좌·우 확인 |
| 모바일 화면 크기 | 390×844와 844×390에서 잘림 없이 주요 부품 표시 확인 |
| 원본 사진 | `Pictures/` 원본은 변경하지 않으며 배포 결과에 포함하지 않음 |
| 임시 파일 | 테스트는 메모리에서 모델을 생성하고 finally에서 자원을 해제; 디스크 임시 작업 파일 없음 |

브라우저 화면은 Codex 내장 브라우저에서 확인했다. 모바일 화면 크기 검증은 실제 아이폰 Safari 확인이 아니다. 회전 제스처와 버튼 계산은 구현 범위가 아니므로 기능 검증도 수행하지 않았다.

**외형 비교 결과**

정면 사진 IMG_0098 기준으로 짙은 파란 본체, 청록색 화면 테두리·서랍, 흰색 4×4 키 배열, 왼쪽 기능 키, OPEN 버튼, 노란 스캐너와 꽃 모양 마이크를 배치했다. 측면·후면 사진을 참고해 본체의 깊이, 상판 경사와 화면 뒷면 두께를 조정했다. 개별 키가 서로 겹치거나 키패드 안에 묻히지 않는지 단위 테스트로 확인했다.

치수·곡률·연결선 경로는 사진으로 추정했다. 캐릭터 스티커는 단순화한 그래픽이며 현재 사진을 직접 매핑한 정밀 텍스처가 아니다. 화면 테두리의 세밀한 단차, 스캐너 곡면과 바닥 내부 구조도 단순화되어 있다. 재질·스티커의 추가 보정은 5단계에서 진행한다.

**남은 사항**

- 3단계 시점 조작과 입력 판정, 4단계 계산·키 눌림 효과는 미구현이다.
- 5단계의 사진 스티커 보정, manifest·홈 화면 아이콘, 모바일 성능과 수명주기 대응은 후속 작업이다.
- Three.js 청크는 약 574 kB, gzip 약 145 kB로 기본 청크 크기 경고가 발생한다. 빌드는 성공했으며 성능 최적화는 실기기 측정과 함께 진행한다.
- 초기 개발 과정에서 그래픽 드라이버의 셰이더 정밀도 경고가 관측되었다. 표시 실패는 없었고 사용하던 폐기된 그림자 옵션은 PCFShadowMap으로 수정했다.
- Actions 워크플로는 준비했으나 원격 푸시, Pages 설정 변경, GitHub Actions 실행과 공개 배포는 수행하지 않았다.
- 아이폰 실기기 기종·iOS별 동작과 FPS는 아직 확인하지 않았다.
